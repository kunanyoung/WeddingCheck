# 03. IA · Sitemap · User Flow

## 1. 정보 구조 (IA)

### 1-1. 계층 구조

```
Wedding Desk Checklist
│
├─ 오늘 (Today)                              [기본 진입 화면 · depth 0]
│   ├─ 오늘 해야 할 업무          (지연 + 오늘 기한 항목)
│   ├─ 전체 진행 요약             (진행 중 예식 수 · 평균 진행률)
│   ├─ 다가오는 일정              (7일 이내 기한)
│   ├─ 오늘 메모                  (작성 + 최근 5건)
│   └─ 최근 완료한 업무           (최근 24시간 체크 항목)
│
├─ 예식 (Events)                             [depth 1]
│   ├─ 예식 목록                  (진행 중 / 보관함 탭)
│   ├─ 예식 등록                  (예식일 → 자동 생성)
│   └─ 예식 상세                  [depth 2]
│       ├─ 요약 헤더              (D-Day · 원형 진행률 · 라벨)
│       ├─ 체크리스트             (12 카테고리 아코디언)
│       ├─ 일정                   (마일스톤 타임라인)
│       ├─ 메모                   (이 예식 메모)
│       └─ 첨부                   (파일 · 링크)
│
├─ 일정 (Schedule)                           [depth 1]
│   ├─ 이번 주 / 이번 달 전환
│   └─ 전체 예식 마일스톤 타임라인
│
├─ 메모 (Memos)                              [depth 1]
│   ├─ 전체 / 예식별 / 일반 필터
│   └─ 태그 필터
│
├─ 템플릿 (Templates)                        [depth 1]
│   ├─ 템플릿 목록
│   └─ 템플릿 편집                [depth 2]
│       ├─ 카테고리 순서 편집
│       └─ 항목 추가 · 삭제 · 순서 · 기한
│
├─ 검색 (Search)                             [오버레이 · depth 0에서 호출]
│   └─ 체크리스트 / 메모 / 일정 결과 그룹
│
└─ 설정 (Settings)                           [depth 1]
    ├─ 알림
    ├─ 표시 (기본 템플릿 · 진행률 계산 방식 · 다크모드)
    ├─ 데이터 (용량 · 백업 · 전체 삭제)
    ├─ 개인정보 원칙
    └─ 앱 정보 (버전 · PWA 설치)
```

### 1-2. 데이터 관계

```
Template  1 ──< (생성 시 스냅샷 복사) ──  Event
Event     1 ──<  ChecklistItem (32)  ──  1 Attachment*  1 Memo*
Event     1 ──<  Memo*
Memo      0..1 ──  Event            (미연결 = 일반 메모)
```

**핵심 규칙**: 예식 생성 시 템플릿 항목을 **복사**합니다. 이후 템플릿을 수정해도
이미 만든 예식은 변하지 않습니다. (FR-TPL-07)

### 1-3. 네비게이션 매핑

| 위치 | 데스크톱 (≥1024px) | 모바일 (<1024px) |
| --- | --- | --- |
| 오늘 | 좌측 사이드바 1번 | 하단 탭 1번 |
| 예식 | 사이드바 2번 | 하단 탭 2번 |
| 일정 | 사이드바 3번 | 하단 탭 3번 |
| 메모 | 사이드바 4번 | 하단 탭 4번 |
| 템플릿 | 사이드바 5번 | 하단 탭 5번 `더보기` 안 |
| 설정 | 사이드바 하단 | 하단 탭 5번 `더보기` 안 |
| 검색 | 상단바 검색창 (`Cmd/Ctrl+K`) | 상단바 검색 아이콘 |
| 예식 등록 | 사이드바 상단 `＋ 예식 등록` 버튼 | 우하단 FAB |

모바일 하단 탭은 5개 고정: `오늘 · 예식 · 일정 · 메모 · 더보기`

## 2. Sitemap (라우트)

| 라우트 | 화면 | depth | 진입 클릭 수 |
| --- | --- | --- | --- |
| `/` | 오늘 | 0 | 0 (앱 실행) |
| `/events` | 예식 목록 | 1 | 1 |
| `/events/new` | 예식 등록 | 2 | 1 (FAB/버튼 직행) |
| `/events/[id]` | 예식 상세 · 체크리스트 | 2 | 2 |
| `/events/[id]?tab=schedule` | 예식 상세 · 일정 | 2 | 3 |
| `/events/[id]?tab=memo` | 예식 상세 · 메모 | 2 | 3 |
| `/events/[id]?tab=files` | 예식 상세 · 첨부 | 2 | 3 |
| `/events/[id]/edit` | 예식 수정 | 3 | 3 |
| `/schedule` | 일정 | 1 | 1 |
| `/memos` | 메모 | 1 | 1 |
| `/templates` | 템플릿 목록 | 1 | 1~2 |
| `/templates/[id]` | 템플릿 편집 | 2 | 2~3 |
| `/settings` | 설정 | 1 | 1~2 |
| `/onboarding` | 첫 실행 안내 | — | 최초 1회 |
| 검색 | 오버레이 (라우트 없음, `?q=` 동기화) | — | 1 |

**최대 depth 3, 모든 기능 3클릭 이내** — 개발 원칙 충족 (`/events/[id]/edit` 만 3클릭,
나머지 주요 기능은 2클릭 이내).

## 3. User Flow

### 3-1. 첫 실행 (온보딩)

```
앱 최초 접속
   ↓
[온보딩 1/3] 이 앱은?
   "예약실 업무를 놓치지 않게 돕는 개인 체크리스트입니다"
   ↓
[온보딩 2/3] 개인정보를 저장하지 않습니다
   "고객 이름·연락처를 입력하는 칸이 없습니다.
    예식은 날짜·시간·홀로 구분합니다."
   ↓
[온보딩 3/3] 데이터는 이 브라우저에만 있습니다
   "서버에 올라가지 않습니다. 브라우저 데이터를 지우면 사라지니
    설정에서 백업을 받아 두세요."
   ↓
기본 템플릿 자동 생성 (tpl_default)
   ↓
┌─ 예식이 없음 → [빈 상태] "첫 예식을 등록해 보세요" → /events/new
└─ 건너뛰기      → /
```

### 3-2. 핵심 플로우 A — 예식 등록 (목표 20초)

```
/ 또는 /events
   ↓ [＋ 예식 등록] 클릭            ← 1클릭
/events/new
   ↓ 예식일 선택 (달력 · 필수)
   ↓ 시간 · 홀 · 별칭 (선택 · 건너뛰기 가능)
   ↓ 템플릿 (기본값 = 최근 사용 템플릿)
   ↓ [저장] 클릭                    ← 2클릭
   │
   ├─ 별칭에 PII 패턴 → 인라인 에러, 저장 차단
   │      "연락처는 저장할 수 없습니다"
   │
   └─ 정상 → 32개 항목 + 기한 자동 생성
          ↓
      /events/[id]  (체크리스트 즉시 표시)
          ↓ 토스트: "13개 마일스톤 일정이 만들어졌습니다"
```

### 3-3. 핵심 플로우 B — 아침 업무 확인 (목표 2분)

```
앱 실행 (PWA 아이콘)
   ↓
/ 오늘
   ↓
[오늘 해야 할 업무] 섹션
   ├─ 지연 3건 (빨강)  ── 클릭 → 체크 → 즉시 목록에서 사라짐 + 진행률 갱신
   ├─ 오늘 5건 (골드)  ── 체크박스 직접 클릭 (화면 이동 없음)
   └─ 전체 완료 → 빈 상태 "오늘 할 일을 모두 마쳤습니다"
   ↓
[다가오는 일정] 7일 이내 항목 확인
   ↓
[오늘 메모] 한 줄 입력 → Enter 저장
```

> 홈에서 체크가 바로 되는 것이 중요합니다. 예식 상세로 들어가지 않아도 체크되어야
> "클릭 최소화" 원칙이 지켜집니다.

### 3-4. 핵심 플로우 C — 상담 중 항목 체크 (목표 30초)

```
검색 (Cmd/Ctrl+K 또는 상단 검색)
   ↓ "5/16" 또는 "그랜드홀" 또는 "식권" 입력
   ↓
결과 그룹
   ├─ 예식     5/16(토) 13:00 그랜드홀   → 클릭 → /events/[id]
   ├─ 체크항목 식권 준비 (5/16 예식)      → 클릭 → 해당 항목으로 스크롤 + 하이라이트
   └─ 메모     "식권은 내일 전달"         → 클릭 → /memos 해당 메모
   ↓
체크박스 클릭 → 완료 시각 자동 기록 → 진행률 갱신
```

### 3-5. 핵심 플로우 D — 예식 당일 (모바일)

```
홈 화면 PWA 아이콘
   ↓
/ 오늘 → [오늘 예식] 카드 강조 배너 (D-DAY)
   ↓ 탭
/events/[id]
   ↓ `당일` 카테고리 자동 펼침 (D-Day면 기본 펼침)
   ↓
□ 최종인원   → 탭
□ 잔금 확인  → 탭
□ 주차 확인  → 탭
□ 특이사항   → 탭
□ 예식 완료  → 탭
   ↓
100% 달성 → 원형 진행률 success 전환 + 확인 시트
   "예식을 완료 처리하고 보관함으로 옮길까요?"  [보관] [나중에]
```

### 3-6. 핵심 플로우 E — 웨딩홀 이직 (템플릿)

```
/templates
   ↓ [기본 템플릿] 우측 ⋯ → 복제
   ↓ 이름 입력: "B웨딩홀"
   ↓
/templates/[id]
   ↓ 필요 없는 항목 삭제      (예: 폐백 카테고리 전체)
   ↓ 새 항목 추가             (예: 야외 세팅 확인 / D-7)
   ↓ 카테고리 순서 변경       (드래그 또는 ↑↓ 키)
   ↓ [기본 템플릿으로 지정]
   ↓
이후 /events/new 의 템플릿 기본값이 "B웨딩홀"
```

### 3-7. 예외 · 에러 플로우

| 상황 | 처리 |
| --- | --- |
| PII 패턴 입력 (차단 대상) | 인라인 에러 + 저장 버튼 비활성. 필드 아래 사유 표시 |
| PII 패턴 입력 (경고 대상) | 저장은 되되 경고 토스트 1회. 되돌리기 제공 |
| LocalStorage 용량 초과 | 모달: "저장 공간이 부족합니다" + 첨부 정리 화면으로 유도 |
| 예식일을 과거로 입력 | 허용 (지난 예식 기록용). `D+n` 표기 + "지난 날짜입니다" 안내 |
| 예식일 미입력 후 저장 | 필드 포커스 이동 + "예식일을 선택해 주세요" |
| 삭제 | 확인 모달 1단계 → 삭제 → 5초 Undo 토스트 |
| 전체 삭제 | `삭제합니다` 문구 직접 입력해야 버튼 활성 |
| 오프라인 | 정상 동작. 별도 안내 없음 (원래 로컬 앱) |
| 브라우저 데이터 삭제 후 재접속 | 온보딩부터 다시 시작. 데이터 유실 안내 |
| 알림 권한 거부 | 설정에 "브라우저 설정에서 허용해 주세요" 안내. 인앱 배지는 계속 동작 |
| 자정 경과 | 창 포커스 복귀 시 D-Day·오늘 목록 재계산 |

## 4. 상태별 화면 (Empty / Loading / Error)

| 화면 | 빈 상태 문구 | 액션 |
| --- | --- | --- |
| 오늘 · 할 일 | "오늘 할 일을 모두 마쳤습니다" | — |
| 오늘 (예식 0건) | "등록된 예식이 없습니다" | `＋ 예식 등록` |
| 예식 목록 | "진행 중인 예식이 없습니다" | `＋ 예식 등록` |
| 보관함 | "보관한 예식이 없습니다" | — |
| 메모 | "메모가 없습니다. 오늘 확인할 내용을 적어 두세요" | 입력창 포커스 |
| 검색 결과 | "'{검색어}' 검색 결과가 없습니다" | 검색어 지우기 |
| 첨부 | "첨부한 파일이 없습니다" | `파일 추가` |
| 일정 | "예정된 일정이 없습니다" | — |

로딩 상태는 LocalStorage 읽기라 사실상 즉시지만, Next.js 하이드레이션 전 1프레임 동안
스켈레톤을 표시해 레이아웃 점프(CLS)를 막습니다.
