# WeddingCheck

OO웨딩홀 **예약실 업무 시스템** 워킹 스켈레톤 프로토타입.
상담 접수부터 예식 당일까지의 준비 상황을 하나의 체크리스트로 관리하고, 같은 데이터를
신랑신부에게 로그인 없이 공유하는 흐름을 구현했습니다.

Claude Design 프로젝트 `WeddingCheck.dc.html` 를 의존성 없는 정적 웹 앱으로 구현한 결과물입니다.

> **데이터 안내** — 이 저장소의 웨딩홀명(`OO웨딩홀`), 직원·고객 이름, 전화번호(`010-0000-0000`
> 형태), 제휴업체명은 모두 화면 시연을 위한 가상 데이터입니다. 실존하는 업체·인물과 관계가
> 없습니다. 체크리스트 23개 항목은 예약실 업무 흐름을 보여주기 위한 일반적인 예식 준비
> 항목이며, 금액은 계약 조건마다 달라 빈칸으로 두었습니다.

## 실행

빌드 도구·패키지 설치가 필요 없습니다.

```
index.html 을 브라우저에서 열기
```

또는 로컬 서버로:

```bash
npx serve .          # http://localhost:3000
```

> Pretendard / Gowun Batang 웹폰트는 CDN에서 불러옵니다. 오프라인에서는 시스템 폰트로
> 대체 렌더링되며 레이아웃은 동일합니다.

## 오늘 상담 기록 (계약 전 단계)

**고객 등록**은 계약이 성사된 고객을 등록하는 기능입니다. 그 앞 단계 — **워킹인 · 컨설팅
상담이 있었다는 사실 자체** — 는 홈 대시보드의 **오늘 상담 기록** 카드에서 따로 남깁니다.
하루에 상담이 몇 건 있었는지 가볍게 세는 것이 목적이라, 고객 등록과 서로를 참조하지 않는
**독립 저장소**(`wdc:v1:consultations`)를 씁니다. 상담 기록을 고객(`CUSTOMERS`)으로 "전환"하는 기능은 없습니다.

| 칸 | 필수 | 설명 |
| --- | --- | --- |
| 상담일 | 필수 | 기본값은 오늘(`TODAY`). 지난 상담은 날짜를 바꿔 적습니다 |
| 상담시간 | 필수 | 시간 선택(`type="time"`) |
| 구분 | 필수 | 워킹인 / 컨설팅 라디오 (`CONSULT_TYPES`) |
| 메모 | **선택** | 자유 입력 한 줄(100자). 비워 두어도 등록됩니다 |
| 작성자 | 필수 | 다른 기록과 같은 규칙 — 로그인 계정이 아니라 직접 고른 이름 |
| 상태 | 자동 | 진행중 · 계약완료 · 상담취소 · 보류 (`CONSULT_STATUSES`) — 등록 시 **진행중** |
| 연결된 예식 | 비어 있음 | `linkedWeddingEventId` — 계약완료 건만 채워집니다 |

- **신랑신부 이름 칸은 두지 않습니다.** 사람이 알아볼 표시가 필요하면 메모 한 줄에만 적습니다
  (`예: OO커플, 특이사항 등`). 메모에 연락처 · 이메일 · 금액으로 보이는 값이 섞이면 저장을 막습니다
  (예식 별칭 · 체크리스트 항목과 같은 검사입니다).
- 목록은 **오늘 날짜 기준 시간순**이고 `10:30 · 워킹인` 형태로 보입니다. 메모가 있는 줄만
  **메모 보기**로 펼칩니다. 왼쪽 체크박스로 여러 건을 골라 **인라인 삭제**하며, 폼이 없는 삭제라
  사이드바의 **기록 담당** 이름으로 활동 이력에 남습니다(시식 후보 삭제와 같은 규칙).
- 다른 날짜로 등록하면 저장은 되지만 오늘 목록에는 오르지 않습니다. 저장 알림과 카드 아래
  안내 줄이 몇 건이 다른 날짜에 있는지 알려 줍니다.
- 첫 방문에만 시연용 세 건(`SEED_CONSULTATIONS`)이 들어가고, 그 뒤로는 브라우저 저장소의 값을 씁니다.

## 계약완료 상담 → 예식 연결 (인라인)

상담 상태를 **계약완료**로 바꾸는 순간, 그 줄 바로 아래에 **예식 연결** 영역이 펼쳐집니다.
연결에 필요한 모든 동작이 오늘 상담 기록 화면 안에서 끝나고 **화면 이동이 없습니다**.

| 갈래 | 하는 일 |
| --- | --- |
| 기존 예식과 연결 | 등록된 예식을 **예식일 · 요일 · 시간 · 홀 · 별칭**으로 검색해 고릅니다. 고르면 즉시 저장됩니다 |
| 새 예식으로 등록 | 예식 예정일 · 예식시간 · 홀만 받는 미니폼. 등록과 동시에 `linkedWeddingEventId` 가 채워집니다 |

- 검색은 낱말을 띄어 적으면 **모두 들어 있는** 예식만 남습니다 (`5.16 그랜드홀`). 기호(`.`·`/`·`-`)는
  무시하므로 `5/16` 으로 적어도 같은 결과입니다.
- 미니폼의 **별칭**은 상담 메모에서 30자까지 자동으로 채워지고, **상담 구분과 메모**는 새 예식의
  스태프 메모(`워킹인 상담에서 연결 · …`)로 넘어갑니다. 예식에는 상담 구분 칸을 따로 두지 않습니다.
- 연결이 끝난 줄에는 상태 옆에 **🔗 예식 연결됨** 배지가 붙습니다. 누르면 연결된 예식을
  예식일자 · 요일 · 예식시간 · 홀 · 별칭으로 짧게 미리보고, 그 자리에서 **연결 해제 · 연결 변경**을 합니다.
- **상담취소 · 보류** 상태에서는 연결 영역이 열리지 않습니다. 계약완료로 열려 있던 영역도 상태를
  내리면 닫힙니다.
- 상태 변경 · 연결 · 해제는 폼 없이 즉시 반영되는 기록이라, 다른 즉시 반영 동작(체크리스트 토글 ·
  시식 후보 삭제)과 같은 규칙으로 **사이드바의 기록 담당** 이름으로 활동 이력에 남습니다.
  새 예식 등록도 이 영역에서는 같은 이름을 씁니다.
- 예식을 지우면 그 예식을 가리키던 연결이 함께 끊기고(`consultStore.unlinkEvent`), 상담 기록 자체는
  그대로 남습니다. 끊긴 건은 다시 "연결 필요"로 잡힙니다.
- 예식 등록의 원칙은 그대로입니다 — **예식일자 · 예식시간 · 홀** 세 값이 모두 같은 예식은 만들 수
  없고, 별칭에 연락처 · 이메일 · 금액으로 보이는 값이 있으면 저장을 막습니다.

**연결 필요 추적** — 계약완료 체크만 하고 연결을 미룬 건을 놓치지 않도록 두 곳에서 보여 줍니다.

- 오늘 상담 기록 카드 위쪽에 `계약완료로 표시했지만 예식과 연결되지 않은 상담이 N건` 안내가 뜨고,
  그 건이 **다른 날짜**에 있으면 오늘 목록 아래 `연결 필요 · 다른 날짜 N건` 묶음으로 함께 보여 줍니다
  (이 줄들은 삭제 체크박스 없이 상태 · 연결만 다룹니다).
- 실적 대시보드의 **상담 → 예식 연결 현황** 카드에서 `계약완료 · 연결 완료 · 연결 필요` 건수와
  연결률을 보고, 연결 필요 목록에서 홈으로 바로 이동합니다.

> 오늘 상담 리스트는 설계대로 **오늘 날짜 기준**입니다. 그래서 다른 날짜 상담의 상태를 바꾸려면
> 그 건이 계약완료 · 미연결로 위 묶음에 올라와 있어야 합니다. (지난 날짜 목록을 날짜별로 열어 보는
> 기능은 아직 없습니다)

## 시식 일정 · 체크리스트는 수기 메모

고객 등록에서 시식 일정을 자동 예약하거나 체크리스트를 자동 생성하지 않습니다.
두 가지는 담당자가 **직접 적는 메모**(`CUSTOMERS.tasting` · `CUSTOMERS.checkMemo`)로 관리합니다.

- 신규 등록 화면의 **수기 메모** 칸 두 개에 자유롭게 적습니다. 형식·길이 제한이 없고 줄바꿈도 그대로 남습니다.
- 저장하면 **고객 상세**의 `시식 일정 메모` · `체크리스트 메모` 카드에 남고, 카드의 **메모 수정** 버튼으로
  언제든 고칩니다(공통 수정 모달을 씁니다). 비워 두면 **미정**으로 표시됩니다.
- 고객 목록의 `시식 일정 메모` 칸에는 메모가 두 줄까지 보이고, 전문은 마우스를 올리거나 상세에서 확인합니다.
- 예식일 D-Day 자동 계산은 그대로 남아 있습니다. 사이드바의 **체크리스트** 메뉴(예약실 양식 23항목)도
  그대로이며, 위 메모는 그 양식과 별개로 적는 자유 메모입니다.

## 수정 · 삭제 (모든 목록 공통)

고객·시식 예약·게시글·제휴업체·상담 기록·회원 — 목록 항목마다 **수정 / 삭제** 버튼이 있고,
동작은 어느 화면에서나 같습니다.

- **수정**은 공통 모달 하나(`editModal`)를 씁니다. 항목 종류마다 어떤 칸을 보여줄지는
  `app.js` 의 `EDIT_FORMS` 한 곳에만 적혀 있어서, 새 목록을 붙일 때 항목 정의만 추가하면 됩니다.
  `optional` 이 아닌 칸을 비우고 저장하면 모달 안에서 오류를 안내합니다.
- **삭제**는 확인 모달을 한 번 거칩니다. 예식을 지우면 그 예식의 시식 예약도 함께 지워지고,
  확인 모달이 몇 건이 함께 사라지는지 미리 알려 줍니다.
- 목록은 `data.js` 원본을 복사해 `state` 안에 두고 고칩니다. **새로고침하면 원본 데이터로
  되돌아갑니다** (프로토타입이라 저장소가 없습니다).

## 체크리스트 항목의 출처

`data.js` 의 `CHECKLIST` 는 예약실에서 쓰는 종이 양식 **`★예식체크리스트.xlsx`** 를 그대로
옮긴 것입니다. 양식의 1~23번 항목을 순서를 바꾸지 않고 옮기고, 성격이 같은 번호끼리 7개
묶음으로만 나눴습니다.

| 묶음 | 양식 번호 | 항목 수 |
| --- | --- | --- |
| 예식 기본 정보 | 1–3 | 3 |
| 식사 · 인원 | 4–6 | 3 |
| 홀 · 기본 구성 | 7–8 | 2 |
| 예식 진행 · 폐백 | 9–13 | 5 |
| 영상 · 음향 · 연출 | 14–18 | 5 |
| 당일 준비물 | 19–20 | 2 |
| 이동 · 정산 | 21–23 | 3 |

- 각 묶음의 `caption`("양식 9–13번")은 종이 양식과 번호를 대조하기 위한 표시입니다.
- 각 항목의 `meta` 는 양식에 인쇄된 안내 문구를 한 줄로 요약한 것입니다.
  (예: *지불보증인원* → "예식 10일 전 변경 불가 · 여유분 10% · 미달 시 보증인원 100% 정산")
- **금액은 계약 조건마다 달라 값을 넣지 않고 빈칸으로 두었습니다.** `data.js` 의 `BLANK`
  상수(`(      )`)가 그 자리이며, 화면에는 `기본구성 (      )원` 처럼 표시됩니다.
  채워 넣을 때는 해당 항목의 `meta` 에서 `${BLANK}원` 을 `560,000원` 처럼 바꾸면 됩니다.
  빈칸이 들어간 항목은 식대·홀대관료·기본구성·스냅·비디오·폐백·식전영상·실시간중계·
  예도·웨딩연주·정산 11곳이고, `data.js` 에서 `BLANK` 로 검색하면 한 번에 찾을 수 있습니다.
- 양식 자체의 회신 기한(**예식 14일 전**)은 `CHECKLIST_DUE` 상수로 두고 체크리스트 화면
  상단에 함께 보여 줍니다. 파일 제출 기한(식전 영상 MP4 · 축가 반주 MP3 = 예식주 수요일)은
  해당 항목의 `meta` 에 적혀 있습니다.
- 양식의 회신처(메일·팩스·전화)는 원본 웨딩홀 정보라 옮기지 않고, 앱의 `STAFF` 연락처를
  씁니다. 실제 운영 시 `STAFF` 값만 바꾸면 됩니다.

양식은 `소인O` / `소인X` 두 시트가 있고 항목 구성은 동일합니다. 소인 단가를 명시한
`소인O` 시트를 기준으로 삼았습니다.

## 상태와 동기화

상태는 `app.js` 의 `state` 객체 한 곳에 모여 있고, 변경은 항상 `setState()` → 전체 재렌더로
흐릅니다. 덕분에 한 곳의 변경이 관련된 모든 화면에 함께 반영됩니다.

- 체크리스트 항목을 토글하면 → 진행률 카드, 사이드바 배지, 고객 목록의 진행률 막대,
  홈 대시보드, 신랑신부 모바일 화면이 모두 같은 값으로 갱신됩니다.
- 게시판 글을 완료 처리하면 → 사이드바 배지와 홈의 "확인 안 한 게시글" KPI가 함께 줄어듭니다.
- 오늘 상담을 등록 · 삭제하면 → 홈의 **오늘 상담 N건** KPI와 그 아래 시간 목록
  (`10:30 · 13:00 · 16:00`), 인사말 문구가 모두 `consultations` 저장소 기준으로 함께 갱신됩니다.
- 상담을 계약완료로 바꾸거나 예식과 연결하면 → 상담 카드의 "연결 필요" 안내와 실적 대시보드의
  **상담 → 예식 연결 현황**(연결 완료 · 연결 필요 · 연결률)이 함께 움직입니다.
- 게시판 글쓰기는 제목·내용·작성자만 받는 자유 게시판입니다. 예식을 지정하지 않고,
  내용 길이·형식에도 제한이 없습니다. 등록한 글은 목록 맨 위에 쌓입니다.
- 재렌더 시 `data-keep` 입력값과 `data-focus-key` 포커스·커서 위치는 보존되므로,
  폼을 작성하는 도중 날짜를 바꿔도 입력한 내용이 사라지지 않습니다.

D-Day 계산의 기준일("오늘")은 `data.js` 의 `TODAY = '2026-02-10'` 입니다. 시연 데이터가
이 날짜를 전제로 작성되어 있어 고정값으로 두었습니다.

색·타이포·반경은 `styles.css` 의 `:root` 변수로 정리되어 있습니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--rose` / `--rose-dark` | `#a9455a` / `#8a3547` | 주요 액션, 강조, 진행률 |

## 원본 디자인 대비 참고 사항

**에셋**

- 히어로 이미지는 원본 PNG(848×1264, 1.9 MB)를 **WebP q=88** 로 변환해 씁니다.
  219 KB 로 89% 줄었고 원본 대비 PSNR 39.4 dB · 최대 채널 오차 18 이라 육안 차이는 없습니다.
  무손실 원본은 `design/hero-photo.png` 에 보관해 두었으니, 화질을 더 올리거나 다른 포맷으로
  다시 뽑을 때 여기서 변환하면 됩니다.
- WebP 는 Chrome 32+ / Firefox 65+ / Safari 14+ / Edge 18+ 에서 지원됩니다. 더 오래된
  브라우저까지 받아야 하면 `app.js` 의 `hero()` 에서 `<img>` 를 `<picture>` 로 감싸고
  PNG/JPEG `<source>` 를 추가하세요.

**보완한 것** (원본이 화면만 있고 동작은 없던 부분)

- 고객 검색창 — 이름·연락처 부분 일치 검색, 결과 없음 안내 추가
- 예식일이 과거인 경우 `D+n` 으로 표기 (원본은 `D--n` 으로 표시됨)
- 모달: Escape 키 / 배경 클릭으로 닫기, 공유 링크는 실제 클립보드 복사
- 접근성: `aria-pressed` · `aria-checked` · `aria-current`, 포커스 링, 축소 모션 존중
- 반응형: 1180 / 1024 / 860 / 720px 브레이크포인트 (넓은 표는 가로 스크롤 컨테이너로 처리)

**아직 동작하지 않는 버튼** — 원본 프로토타입과 동일하게 화면만 있는 상태입니다.
백엔드가 붙는 시점에 연결하면 됩니다.

- 상담 기록 `＋ 기록 추가`
- 체크리스트 `파일 선택` / 모바일 `＋ 식전 영상 · 축가 음원 제출하기`
- 게시판 `메모 등록`
- 제휴업체 `안내 전달`

## 실제 서비스로 넘어갈 때

`data.js` 의 상수를 API 응답으로 바꾸는 것이 첫 단계입니다. 화면 코드는 `WCData` 의 모양만
같으면 그대로 동작하도록 데이터와 렌더를 분리해 두었습니다.
