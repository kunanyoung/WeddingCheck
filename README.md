# WeddingCheck

OO웨딩홀 **예약실 업무 시스템** 워킹 스켈레톤 프로토타입.
상담 접수부터 예식 당일까지의 준비 상황을 하나의 체크리스트로 관리하고, 같은 데이터를
신랑신부에게 로그인 없이 공유하는 흐름을 구현했습니다.

Claude Design 프로젝트 `WeddingCheck.dc.html` 를 의존성 없는 정적 웹 앱으로 구현한 결과물입니다.

> **데이터 안내** — 이 저장소의 웨딩홀명(`OO웨딩홀`), 직원·고객 이름, 전화번호(`010-0000-0000`
> 형태), 제휴업체명은 모두 화면 시연을 위한 가상 데이터입니다. 실존하는 업체·인물과 관계가
> 없습니다. 체크리스트 23개 항목은 예약실 업무 흐름을 보여주기 위한 일반적인 예식 준비
> 항목이며, 금액은 계약 조건마다 달라 빈칸으로 두었습니다.

## 실행

빌드 도구·패키지 설치가 필요 없습니다.

```
index.html 을 브라우저에서 열기
```

또는 로컬 서버로:

```bash
npx serve .          # http://localhost:3000
```

> Pretendard / Gowun Batang 웹폰트는 CDN에서 불러옵니다. 오프라인에서는 시스템 폰트로
> 대체 렌더링되며 레이아웃은 동일합니다.

## 파일 구조

```
★예식체크리스트.xlsx  예약실 실제 종이 양식 (체크리스트 항목의 출처)
index.html          앱 셸 (#app 하나만 두고 나머지는 JS가 렌더)
styles.css          디자인 토큰(:root 변수) + 전체 컴포넌트 스타일
data.js             시연용 고정 데이터 — 전역 `WCData` 로 노출
app.js              상태 · 화면 렌더 · 이벤트 (외부 의존성 없음)
assets/
  hero-photo.webp   로그인 / 모바일 화면 히어로 이미지 (848×1264, 219 KB)
design/
  WeddingCheck.dc.html   Claude Design 원본 (참고용, 실행에는 불필요)
  support.js             원본이 쓰던 dc-runtime (참고용)
  hero-photo.png         히어로 이미지 원본 무손실 PNG (1.9 MB)
```

## 체크리스트 항목의 출처

`data.js` 의 `CHECKLIST` 는 예약실에서 쓰는 종이 양식 **`★예식체크리스트.xlsx`** 를 그대로
옮긴 것입니다. 양식의 1~23번 항목을 순서를 바꾸지 않고 옮기고, 성격이 같은 번호끼리 7개
묶음으로만 나눴습니다.

| 묶음 | 양식 번호 | 항목 수 |
| --- | --- | --- |
| 예식 기본 정보 | 1–3 | 3 |
| 식사 · 인원 | 4–6 | 3 |
| 홀 · 기본 구성 | 7–8 | 2 |
| 예식 진행 · 폐백 | 9–13 | 5 |
| 영상 · 음향 · 연출 | 14–18 | 5 |
| 당일 준비물 | 19–20 | 2 |
| 이동 · 정산 | 21–23 | 3 |

- 각 묶음의 `caption`("양식 9–13번")은 종이 양식과 번호를 대조하기 위한 표시입니다.
- 각 항목의 `meta` 는 양식에 인쇄된 안내 문구를 한 줄로 요약한 것입니다.
  (예: *지불보증인원* → "예식 10일 전 변경 불가 · 여유분 10% · 미달 시 보증인원 100% 정산")
- **금액은 계약 조건마다 달라 값을 넣지 않고 빈칸으로 두었습니다.** `data.js` 의 `BLANK`
  상수(`(      )`)가 그 자리이며, 화면에는 `기본구성 (      )원` 처럼 표시됩니다.
  채워 넣을 때는 해당 항목의 `meta` 에서 `${BLANK}원` 을 `560,000원` 처럼 바꾸면 됩니다.
  빈칸이 들어간 항목은 식대·홀대관료·기본구성·스냅·비디오·폐백·식전영상·실시간중계·
  예도·웨딩연주·정산 11곳이고, `data.js` 에서 `BLANK` 로 검색하면 한 번에 찾을 수 있습니다.
- 양식 자체의 회신 기한(**예식 14일 전**)은 `CHECKLIST_DUE` 상수로 두고 체크리스트 화면
  상단에 함께 보여 줍니다. 파일 제출 기한(식전 영상 MP4 · 축가 반주 MP3 = 예식주 수요일)은
  해당 항목의 `meta` 에 적혀 있습니다.
- 양식의 회신처(메일·팩스·전화)는 원본 웨딩홀 정보라 옮기지 않고, 앱의 `STAFF` 연락처를
  씁니다. 실제 운영 시 `STAFF` 값만 바꾸면 됩니다.

양식은 `소인O` / `소인X` 두 시트가 있고 항목 구성은 동일합니다. 소인 단가를 명시한
`소인O` 시트를 기준으로 삼았습니다.

## 상태와 동기화

상태는 `app.js` 의 `state` 객체 한 곳에 모여 있고, 변경은 항상 `setState()` → 전체 재렌더로
흐릅니다. 덕분에 한 곳의 변경이 관련된 모든 화면에 함께 반영됩니다.

- 체크리스트 항목을 토글하면 → 진행률 카드, 사이드바 배지, 고객 목록의 진행률 막대,
  홈 대시보드, 신랑신부 모바일 화면이 모두 같은 값으로 갱신됩니다.
- 게시판 메모를 완료 처리하면 → 사이드바 배지와 홈의 "미확인 부재중 메모" KPI가 함께 줄어듭니다.
- 재렌더 시 `data-keep` 입력값과 `data-focus-key` 포커스·커서 위치는 보존되므로,
  폼을 작성하는 도중 날짜를 바꿔도 입력한 내용이 사라지지 않습니다.

D-Day 계산의 기준일("오늘")은 `data.js` 의 `TODAY = '2026-02-10'` 입니다. 시연 데이터가
이 날짜를 전제로 작성되어 있어 고정값으로 두었습니다.

## 디자인 토큰

색·타이포·반경은 `styles.css` 의 `:root` 변수로 정리되어 있습니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--rose` / `--rose-dark` | `#a9455a` / `#8a3547` | 주요 액션, 강조, 진행률 |
| `--bg` / `--surface` | `#f7f4f1` / `#fff` | 페이지 배경 / 카드 |
| `--ink` / `--muted` / `--muted-2` | `#221d1b` / `#6f6560` / `#8b817b` | 본문 · 보조 텍스트 |
| `--nav-bg` | `#241f1e` | 사이드바 |
| `--font-serif` | Gowun Batang | 브랜드·헤드라인 |
| `--font-sans` | Pretendard | 본문 UI |

상태 배지는 `tone-rose / green / amber / violet / neutral` 5종으로 통일했고, 매핑은
`data.js` 의 `TONE` 에 모아두었습니다. (예: `계약완료`→green, `상담중`→violet, `조율중`→amber)

## 원본 디자인 대비 참고 사항

**에셋**

- 히어로 이미지는 원본 PNG(848×1264, 1.9 MB)를 **WebP q=88** 로 변환해 씁니다.
  219 KB 로 89% 줄었고 원본 대비 PSNR 39.4 dB · 최대 채널 오차 18 이라 육안 차이는 없습니다.
  무손실 원본은 `design/hero-photo.png` 에 보관해 두었으니, 화질을 더 올리거나 다른 포맷으로
  다시 뽑을 때 여기서 변환하면 됩니다.
- WebP 는 Chrome 32+ / Firefox 65+ / Safari 14+ / Edge 18+ 에서 지원됩니다. 더 오래된
  브라우저까지 받아야 하면 `app.js` 의 `hero()` 에서 `<img>` 를 `<picture>` 로 감싸고
  PNG/JPEG `<source>` 를 추가하세요.

**보완한 것** (원본이 화면만 있고 동작은 없던 부분)

- 고객 검색창 — 이름·연락처 부분 일치 검색, 결과 없음 안내 추가
- 예식일이 과거인 경우 `D+n` 으로 표기 (원본은 `D--n` 으로 표시됨)
- 모달: Escape 키 / 배경 클릭으로 닫기, 공유 링크는 실제 클립보드 복사
- 접근성: `aria-pressed` · `aria-checked` · `aria-current`, 포커스 링, 축소 모션 존중
- 반응형: 1180 / 1024 / 860 / 720px 브레이크포인트 (넓은 표는 가로 스크롤 컨테이너로 처리)

**아직 동작하지 않는 버튼** — 원본 프로토타입과 동일하게 화면만 있는 상태입니다.
백엔드가 붙는 시점에 연결하면 됩니다.

- 상담 기록 `＋ 기록 추가`
- 체크리스트 `파일 선택` / 모바일 `＋ 식전 영상 · 축가 음원 제출하기`
- 게시판 `메모 등록`
- 제휴업체 `안내 전달`

## 실제 서비스로 넘어갈 때

`data.js` 의 상수를 API 응답으로 바꾸는 것이 첫 단계입니다. 화면 코드는 `WCData` 의 모양만
같으면 그대로 동작하도록 데이터와 렌더를 분리해 두었습니다.
